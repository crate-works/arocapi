arocapi answers `POST /search` through a search backend. This guide uses `OpenSearchBackend`, which keeps one search
document per entity in an OpenSearch index. Your code supplies the documents: arocapi never builds them from the
database.

:::note[Deposits are coming]
Support for the RO-Crate API's [deposit](https://ro-crate-api.crate-works.org/docs/deposit) routes is coming soon.
RO-Crates deposited through the API will be indexed by arocapi, so you won't need separate code to keep the database
and search index in step for them.
:::

## Declare the search fields

Create the backend in a module of its own, so the server and your scripts share it. Each field is declared once, with a
type and the roles clients may use it for:

<Code code={gettingStartedSearch} lang="ts" title="src/search.ts" />

- **`name` and `description`** are `text`, so basic search matches their words, with `name` weighted higher.
  `name` is also a sort.
- **`entityType`** is a `keyword`, matched exactly. As a facet, the response counts each type, and clients can filter
  by it.

Nothing else is searchable: a field is only filtered, faceted or sorted on if you declare it.
[Search](/configuration/search/) lists every type and role, and `OpenSearchBackend`'s options, such as `indexName`
(default `entities`).

## Create the index

`createIndex()` builds the index mapping from the declarations:

<Code code={createIndex} lang="ts" title="scripts/create-index.ts" />

```sh
node --env-file=.env scripts/create-index.ts
```

Running it again leaves a matching index alone. If you later change a declaration, it throws, naming the field; delete
the index, create it again and index your entities.

## Index documents

Add an entity to the database first, then index its search document: its `id` and a value for each declared field you
have. `search.index([...])` is typed from the declarations, so an undeclared field or a wrong value type fails to
compile. arocapi loads each hit's entity from the database, and leaves out a hit with no entity.

Next, write [your first API](/getting-started/first-api/), which adds an entity to the database and the index.
